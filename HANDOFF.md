## 1. Background

**La Robe Maldives** runs a live, revenue-generating internal **Orders PWA**:
- Supabase backend (project ref `oyzfkknoeweafiqirurv`), hosted on GitHub Pages

## 3. Non-negotiable rules

1. **Never modify production directly.** All schema changes are migration files in `supabase/migrations/`, tested on staging first.
2. **The live admin app must keep working** at every step of the conversion.
3. **RLS on every table.** Tenant isolation enforced at the database layer, not just the frontend.
4. **Never expose to the public:** cost prices, stock quantities, expenses, staff data, profit figures.
5. **Never trust the cart.** Prices, promotions, and totals are recalculated server-side.
6. Secrets live in `.env` (git-ignored). Use **staging** credentials for development. Never commit keys or tokens.
7. Plan before coding: propose a plan for each phase and wait for approval.
8. One phase per branch (e.g. `phase-1-tenancy`); merge to `main` only after review.

## 6. Public storefront layer (Phase 2)

Resolve tenant by subdomain/slug (e.g. `larobe.<platform>.mv`; custom domains later).

Edge Functions (or tightly scoped RPCs), all taking tenant slug:
- **`catalog`**: active products with selling price, images, stock *status* only (in stock / low / pre-order), active promotions. No cost or quantities.
- **`place_order`**: validates prices server-side, applies promotions, reserves stock atomically via `process_stock_change`, inserts order with `source = 'web'`, status `New`. Pre-order items do not reduce stock until allocated.
- **`track_order`**: order number + phone → status only.

Guest checkout safeguards:
- Cloudflare Turnstile on checkout
- Rate limits per phone and IP
- Maldivian phone format validation
- Cap on unpaid/COD orders per phone number

Payment handling:
- **Transfer:** slip uploaded to a **private** storage bucket; customer-entered amount stored; order status `Payment pending verification`; flag if entered amount ≠ order total.
- **COD:** straight into normal order flow.
- **Pre-order:** deposit (tenant setting: % or full) paid by transfer, expected arrival date shown, separate pre-order queue.
